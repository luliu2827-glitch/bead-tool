# 拼豆电子图纸工具 · Electronic Bead Tool v1.0

> 稳定冻结版本（2026-08-18，对应 git 提交 `ebacb60`）

## 版本定位

这是一个**电子拼豆辅助工具**（照图 / 参考填色），**不是图片识别工具**。

- 用途：在电脑或平板（iPad）上，对照拼豆参考图逐格完成电子拼豆、导出 PNG 图纸、保存 / 读取进度。
- 不提供、也不扩展：图片识别自动生成数字图纸、Pattern Layer、识别结果面板、识别颜色统计。

## 已完成核心功能

| 功能 | 说明 |
|---|---|
| 上传参考图 | 上传成品拼豆图片作为制作参考（Reference Layer），可独立移动 / 缩放 / 调透明度 / 隐藏 |
| 创建空白拼豆画布 | 自定义行列数新建空白画布（Canvas Layer） |
| 电子填色 | 选择 MARD 颜色逐格填色 |
| 吸色 | 读取画布上某格当前颜色 |
| 橡皮擦 | 擦除单格填色 |
| 填充 | 区域 / 同色填充 |
| 撤销 / 重做 | 笔画式撤销 / 重做（含锁定状态） |
| 锁定 | 一次性批量锁定已填格，锁定格禁止修改 |
| 高亮颜色 | 高亮当前选中颜色，便于辨认 |
| MARD 色卡 | 内置 MARD 标准 / 全量色卡，含 LAB 数据用于颜色匹配 |
| Canvas / Reference 独立移动缩放 | 画布与参考图各自独立的变换，互不干扰 |
| 参考图透明度调整 | 叠加模式下调整参考图透明度 |
| 叠加模式 / 分栏模式 | 参考图两种显示方式，可切换；编辑功能始终完整 |
| 移动端操作 | 移动端抽屉侧栏、双指捏合缩放画布、单指移动 / 填色 |

> 注：顶部「⚡ 生成图纸」为既有功能（上传图片 → 像素化生成网格），属于 `ebacb60` 基线的一部分，已随冻结版本保留。若后续希望将其纳入「图片识别」范围并移除，请单独提出（那会改动现有交互）。

## 暂不包含的功能（已确认不扩展）

- 图片识别自动生成数字图纸
- Pattern Layer（独立数字化图纸槽）
- 识别结果面板 / 识别颜色数量统计
- 自动四角检测、OpenCV、AI / API 等识别增强

## 技术架构

- 纯静态站：HTML / CSS / 原生 JS，**无后端、无构建步骤、无第三方运行时依赖**。
- 数据模型：`grid.cells`（Int16Array 调色板索引，-1 空）、`done` / `locks`（Uint8Array）。
- Canvas Layer 与 Reference Layer 为完全独立的状态 + 独立 DOM + 独立变换；叠加 / 分栏仅切换 CSS 显示方式，不参与坐标计算。
- 部署目标：GitHub Pages，推送后约 1–2 分钟自动重建，无 build。

## 文件结构

```
index.html                 入口页面（顶部工具栏 + 侧栏 + 画布 / 参考图）
css/style.css              全部样式（含移动端断点、叠加 / 分栏、统计表）
js/app.js                  主应用逻辑（编辑、锁定、撤销、参考图变换、缩放、生成图纸）
js/bead-palette.js         色卡渲染 / 取色 / 颜色匹配工具
js/palettes.js             色卡注册表
data/palettes/*.js         MARD 标准 / 全量色卡数据（含 lab 坐标）
test/headless-mobile-test.js  无头 DOM 桩测试（172 项，覆盖核心逻辑）
.nojekyll                  GitHub Pages 关闭 Jekyll
```

> 说明：`sample-image.png` 与 `nul` 为仓库内的无用 / 临时文件，已被 `.gitignore` 排除，不会随站点部署。

## 本地运行

直接用浏览器打开 `index.html` 即可（无需服务器）。若浏览器限制本地文件读取，可用任意静态服务器，例如：

```bash
python3 -m http.server 8080
# 然后访问 http://localhost:8080/
```

## 部署（GitHub Pages）

将本目录推送到 GitHub 仓库的 `main` 分支，在仓库 Settings → Pages 选择 `main` 分支根目录即可。站点为静态资源，无需构建。

## 冻结说明

本版本为稳定冻结版本，**不再新增图片识别类功能**，也不重构已稳定的 Canvas / Reference 图层逻辑。后续如需改动，请基于本提交评估影响范围。
